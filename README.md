# CS 350 Portfolio

## Project Summary

For my CS 350 portfolio, I chose my Milestone 3 project and my final thermostat project. These projects helped me learn how software can communicate with hardware using a Raspberry Pi. In Milestone 3, I worked with hardware such as LEDs, buttons, and an LCD screen. For the thermostat project, I created a system that could read temperature and use different states for heating, cooling, and off. Both projects gave me experience working with hardware and software together.

## What Did I Do Well?

I think I did well with testing and solving problems. During these projects, I learned that the code is not always the reason something does not work. Sometimes I had to check the wiring, GPIO pins, hardware connections, or libraries. Testing each part separately helped me find problems without changing parts of the project that were already working.

## Where Could I Improve?

I could improve by spending more time planning before I start coding. There were times when I had to go back and figure out why certain parts of my code were not working the way I expected. I also want to improve my Python skills so I can become more comfortable writing and understanding code on my own.

## Tools and Resources

Some of the resources that helped me during this course were the course materials, wiring diagrams, documentation, and examples from previous assignments. I also learned how useful GitHub can be for saving projects and keeping track of my work. These are resources I can continue using when I work on future projects.

## Transferable Skills

One of the biggest skills I learned from these projects was troubleshooting. I learned how to break a large problem into smaller parts and test each part separately. I also gained experience with Python, GPIO pins, state machines, sensors, buttons, LEDs, and displays. I can use these skills in future programming courses and other projects that involve software and hardware.

## Making My Projects Maintainable, Readable, and Adaptable

I tried to keep my projects organized by separating different parts of the program and using clear names in my code. I also used comments to explain what different sections were doing. State machines helped organize the different actions of the programs. Keeping the code organized makes it easier to read, fix, and change if I need to add something later.
